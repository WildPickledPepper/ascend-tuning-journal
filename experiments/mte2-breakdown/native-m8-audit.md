# 当前原生 M8 MatMul：搬运参数核对与 L1/L0 配平实验

本次先核对原生实现，再按已有测量推导改动。用户随后要求继续实施、完成整模型验证、提交 Git，最后清理本账号6号卡服务；7号卡不恢复。保持单卡 BF16，不重新编写 NPU 内核。

## 1. 算子基本信息

- 上板：Ascend910B2、CANN9.1.0，原生 `F.linear/aclnnMatmul`、ND BF16，23核，M8。
- 升维 N34816/K5120、降维 N5120/K17408，原生 key 98499/98513。
- 160B tiling、200B host参数包来自已有原生探针的实际下发；按安装版 TBE `gemm_tiling_util.get_tiling_key` 字段顺序解析，并与指令参数、DBI 和 PMU 核验。
- 两个入口所在原始 ELF SHA256 均为 `444d3ac5ab6c83b0321b32f7b2a66330de45b0eb215b0c44b8f62c3f2f2a227f`。更改的是实验进程的下发 tiling，没有改 ELF、权重或共享 CANN。
- 适配器按key/dtype/M/N/K选择，草稿模型若使用同样M8形状也会匹配；整模型按Model ID区分主/草稿，不能宣称只改了主模型。M1词表投影不在匹配范围内。
- 整模型旧采样没有160B下发包，因此不将原生同形状探针冒充旧模型逐次参数原件；本次完整模型另用受限适配器的实际匹配计数和图审计确认应用。

## 2. 关键数据 TOP5

### 原生实现已经使用哪些策略

| 项目 | 升维 | 降维 |
|---|---:|---:|
| 实际 MMAD，M×N×K | 8×256×64 | 8×112×64 |
| L0分配的M方向粒度 | 16 | 16 |
| 单次权重搬入L1，N×K | 256×256 | 112×512 |
| 单个权重L1 buffer | 128KiB | 112KiB |
| 权重L1 buffer数量 | 2 | 2 |
| 一包供几个K方向MMAD | 4 | 8 |
| A/B的L1总分配 | 416KiB | 256KiB |
| core0输入搬入指令数 | 1 | 68 |

| core0 MMAD数 | 480 | 544 |

**大包、小M和错峰均有对应机制。** 这里是TBE生成的MatMulV2，不能把存在这些机制写成已使用Ascend C的`CFG_MDL`模板。

原生二进制仿真完成0/1/22核解析，均有END。MMAD寄存器按安装版`tik_params.py`的K/N位置12/24位解析，实际M=8；不是看到L0按16分配便宣布计算补到16，更不是补到128。升维权重两个L1缓冲交替位于160/288KiB；降维位于32/144KiB。

上板DBI及仿真都看到各核K起点不同。例如core0从K0开始，core1升维从K4864、降维从K16896开始；`close_k_shift=0`与安装调度器的`shift_block_access`路径相符。存在错峰不等于所有访问冲突已消除，但不能再推荐“补开错峰”作为已知缺失项。

### 权重恰好读一遍，输入由L2复用

把全部23核GM→L1原始记录中的权重区间排序，逐段验证首尾相接、无重叠无缺口：升维356515840B、降维178257920B，均等于逻辑权重字节。源地址的连续段都满足512B对齐；它们是DBI描述的逻辑行片段，不是物理HBM事务计数。

| 读源几何 | 升维 | 降维 |
|---|---:|---:|
| 每行连续有效源数据 | 512B | 1024B |
| 源行起点跨度 | 10240B | 34816B |
| 全核输入读取字节 | 1884160B | 12812288B |
| 单份输入实际字节 | 81920B | 278528B |
| 假设重复输入命中时的读命中率 | 0.502857% | 6.559767% |
| 上板L2读命中率 | 0.505273% | 6.564019% |

命中率数值高度吻合输入复用的预测，但不是按地址直接分离的PMU命中标签。它支持L2已在服务重复输入，不能凭低命中率宣布缓存没发挥作用。权重本身是主要的流式读取部分。

### 两级分块回修与上板结果

第一版只改善L1源读取几何：降维K块512→1024；升维在保持128KiB权重buffer时，N256→128/K256→512。前者L1占512KiB；后者仍416KiB。都在容量内，保持23核和已有错峰。

结果显示MTE2活动降低，**总时间却增加**。据此回到L0：升维第一版MMAD次数会翻倍；降维每次大包下的内层调度仍然过细。第二版将L0 K64→128，且两组L0B双缓冲仍分别不超过64KiB容量。不是盲扫参数。

每格为3次Default kernel replay均值，单位μs；使用完整物理工作集的合成BF16权重，重放清L2。

| 对象 | 原生 | 只调整L1 | L1/L0配平 |
|---|---:|---:|---:|
| 升维kernel | 274.359 | 285.832 | 270.419 |
| 升维MTE2活动 | 261.039 | 250.273 | 257.531 |
| 升维Scalar活动 | 88.149 | 159.494 | 87.719 |
| 降维kernel | 150.436 | 170.863 | 141.750 |
| 降维MTE2活动 | 127.168 | 114.562 | 123.398 |
| 降维Scalar活动 | 95.859 | 90.350 | 48.957 |

第二版升维耗时降低1.436%、降维降低5.774%；不把它们当作整模型提升。活动时间有重叠，不能逐列相加或将差额命名为纯HBM服务时间。

第二版另以原二进制做单核指令结构复核（物理blockdim1、逻辑n_dim23，只核对core0，不与全芯片仿真比时延）：

| 项目 | 升维第二版 | 降维第二版 |
|---|---:|---:|
| MMAD M×N×K | 8×128×128 | 8×112×128 |
| core0 MMAD数 | 480，未增加 | 272，原来544 |
| 权重单包 | 128×512，128KiB | 112×1024，224KiB |
| core0权重搬入次数 | 120，未增加 | 34，原来68 |
| 单行连续读取 | 1024B | 2048B |

两个单核仿真均完整结束。修改前的两份23核仿真bin已通过编译版Insight `source/api/instructions/dynamic`核对core0指令次数和Process Bytes；`source/details/baseInfo`与`memoryGraph`为空，不当作有效证据。

### 数值与图回放验证

每版测试两组形状，各4组输入（3种随机幅度及零输入），共1277952个BF16输出比较；全部有限，相对L2差约数个10^-5，所有图回放与对应候选输出逐位一致。**候选与原生不是逐位一致**：改变分块/错峰后的K累加顺序产生少量末位差异。没有量化或改成低精度权重，也不能据小样本宣称广泛精度无损；整模型继续核对输出及公开评分。

这里的“每版”指第一、二版。随后第三版保留原来的L1几何、K循环起点和大块遍历顺序，只调整L0：降维N112/K64→N112/K128。L1仍256KiB、权重一包仍112KiB，不减少HBM读取字节；L0B双缓冲56KiB，模型启动时只匹配降维入口。第三版测试的1277952个输出全部与原生逐位一致，两组各4次图回放也一致。这是已测样本的结论，不推广为任意输入的逐位保证。

第三版上板3次均值：降维143.190μs，相对原生150.436μs降低4.817%；Scalar活动95.859→55.039μs，Cube活动18.866→14.907μs。MTE2活动反而127.168→132.083μs，说明这版收益来自片内调度/计算分块配平，不能称HBM供数提速4.8%。升维273.559μs仅降低0.292%，Scalar活动增加，因此整模型不采用升维第三版。三版实际下发参数各3次已验证前152B一致，尾部8B保持原值且不解释其语义。

## 3. 核心瓶颈 TOP5

1. 必需权重读取仍占主要开销，原生已经做到本次GM→L1权重字节不重复；不能靠删除重复读取来消除大头。
2. 搬运几何与L0调度必须联合考虑。第一版MTE2更短却整体更慢，升维Scalar活动明显增加；第二版配平后才获得单算子小幅收益。
3. 小M和错峰已存在。24个物理核中使用23核也有离散分块原因：升维136个N块每核6个、降维46个N块每核2个；简单把blockdim改24不会自动缩短每核最大工作量。
4. 降维片内调度存在小幅余量：第三版降低Scalar/Cube活动并缩短kernel，但没有减少权重字节或MTE2活动，HBM供数问题仍在。
5. 整模型还包括未修改的其他矩阵乘与草稿词表投影；基线128token采样中M1词表投影190次、合计363.706ms。不能把某一个FFN算子的改善比例直接当整网收益。

## 4. 优化建议 TOP5

- 只以整模型对照结果判断采用与否。保持相同checkpoint、MTP7、BF16状态、草稿FULL图、主图capture8，同题同计时。热切换因Attention更新句柄107033失败后已禁用；改为独立启动优化版，不能再宣称两轮保持相同物理权重地址。
- 适配器是版本/形状受限的实验代码，改变原生二进制的tiling，不是通用vLLM配置；未知参数组合拒绝处理。共享CANN、驱动和其他用户环境保持原状。
- 不采用第一版仅放大L1的方案，第二版也不采用。最终仅降维第三版保留为可复现实验，未设为默认配置；单次四题0.466%的差额不足以证明稳定的整模型提升。
- 按用户最新要求，完成记录及Git提交后清理本账号6号卡服务；不运行历史恢复6/7号服务的脚本。
- 后续如复核这份实验，必须在服务启动、图捕获之前设定模式；保持同一模型/请求/图配置，重新检查BF16输出和完整模型，禁止用热重捕获替代独立启动。
