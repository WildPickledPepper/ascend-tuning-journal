# 单张910B2小规模原生MTP头训练

用户授权用独立训练集、冻结主模型BF16，只训练原生MTP头。随后明确缩小评测到原来相同的四题，**不再跑128题，不重新测原生基线**。训练和候选模型保留在私有环境。

## 数据怎样产生

固定[OpenAI GSM8K](https://github.com/openai/grade-school-math)的3101c7d5072418e28b9008a6636bde82a006892c版本。7473道train题经大小写/非字母数字归一化去除与全部1319道test的重合，再按种子20261021抽取64道训练、8道独立验证。与实际旧评测文件再次核对：重合0；送服务器的选择文件只有问题，没有官方答案。

原始27B在单卡6、BF16、原生MTP7及图模式下生成回答，每题最多256个新token。72题合计13228个生成token；部分回答达到长度限制，不宣称所有回答完整或正确。随后对问题＋生成回答做完整teacher-forced prefill，采主模型最后归一化hidden states，prompt位置不计损失。每条核对input IDs、position、BF16形状及最后位置greedy下一token；64/8份特征分别保存。**监督答案和hidden均来自27B，并非使用数据集参考答案。**

## 单卡训练及冻结证明

先退出27B，再在同一卡离线训练小头。使用[SpecForge固定源码](https://github.com/sgl-project/SpecForge/blob/03f3682ea852b73488d62dab4cd539033cc60e3e/specforge/core/mtp.py)的实际MTP模型、损失及BF16优化器组件；独立副本沿用[入口核对](../mtp-training-audit/README.md)的两处兼容修复。这里使用直接小训练循环，未运行完整社区CLI/FSDP流程。

- 15个原生MTP tensor，共424699392个可训练参数；embedding/lm_head另2542796800参数冻结，主64层不加载到训练进程。
- BF16前向和模型权重；仅可训练头保留FP32 master权重和Adam状态。
- batch1、梯度累积4、两轮、32次更新，lr2e-5、10% warmup、cosine、clip1.0。按实际生成token数加权梯度。
- **单步teacher-forced交叉熵，未训练七步递归轨迹。** 原生一层仍在推理中递归起草七次。
- 冻结两张词表训练前后按字节核对相同且无梯度。训练结束11/15头tensor在BF16中发生变化。
- 按8道验证题CE从两个已训练epoch中选较好者：epoch2。没有用测试题选择检查点或调参；没有把原生头混入“已训练检查点”的选择。

| 检查点 | 验证CE，越低越好 | 单步teacher-forced准确率 |
|---|---:|---:|
| 原生头 | 0.241323 | 92.6063% |
| epoch1 | 0.273375 | 90.8811% |
| epoch2，选中候选 | 0.256971 | 91.8053% |

验证没有改善。训练过程中平均CE为0.293892/0.101619，这是优化过程均值，不是固定训练集端点评测；不能把它当成独立泛化提升。训练allocated峰值15282614784B，reserved峰值15590227968B。

候选导出只在独立目录重写包含MTP的一份shard，其余17份权重shard链接原文件。重写shard中的一个非MTP tensor读回逐字节相同；原目录未写、索引不变。详见[导出代码](build_candidate.py)。

## 四题验证

只使用既有相同四题、同公开评测器及生成参数、单并发、2048输出上限、greedy、自然结束；64token预热后才取计数差。单卡BF16/TP1/K7、主与草稿图capture8、SSM BF16、ctx4096、预算0.97，不启用独立MatMul补丁。正常计时没有profiler，也没有特征采集hook。

结果写入[过滤证据](../../evidence/2026-10-21/mtp-small-train.json)。[复算程序](analyze.py)验证生成参数、评测器SHA、运行图配置及计数关系；旧原生基线复用此前三轮中位数59.386318token/s，接受率56.892231%。新旧不是同时测量，四题仅作小规模判断，不代表完整128题或长期精度。

## 实际结果与采用判断

| 指标 | 原生MTP7既有基线 | 本次训练头 |
|---|---:|---:|
| 端到端token/s | 59.386，三轮中位数 | 52.861，单轮 |
| 七候选接受率 | 56.892% | 47.313% |
| 验证轮数 | 171 | 202 |
| 计数口径token/轮 | 4.982 | 4.312 |
| 输出token | 844 | 867 |
| 各题输出长度 | 137/44/575/88 | 137/44/598/88 |
| 答案得分 | 4/4 | 4/4 |
| 服务端平均TTFT | 313.717ms，匹配旧单轮 | 328.577ms |

本次吞吐比旧中位数低10.989%，接受率低9.580个百分点，生成长度也发生变化。**不采用新头，继续保留原生MTP7方案。** 两个验证集指标均未改善，与测试下降方向一致；64题单步训练未取得七步推理收益。现有结果不能单独确定是数据量、学习率、特征路径还是递归目标造成下降，不追加扫参或训练。

核对发现客户端复用版本有一项响应元数据差异：旧基线请求return_token_ids=True，本次未请求；题目、采样和生成参数一致。新回执没有token IDs，不能声称逐token一致；这也不是字节级完全相同HTTP对照，不为补元数据再启动模型。前三题中第三题最终内容不同，输出多23token，原始回答留私有环境。
