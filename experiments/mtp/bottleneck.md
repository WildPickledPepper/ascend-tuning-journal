# MTP 后的瓶颈：矩阵乘仍为主，图外流程出现次要开销

分析时间：2026-10-19 16:17（Asia/Shanghai）。只读取现有 32-token 采样，未启动新模型测试或修改服务。

## 主要结论

主瓶颈仍是大矩阵乘读取和搬运权重。两组 FFN 约占连续解码窗口 46.3%，其余矩阵乘含词表投影约占 26.9%；合计约 73.1%。MTP 减少了主模型执行轮数，未消除每轮遍历权重的成本。

| 连续解码窗口内的工作 | 累计时间 | 占窗口 |
|---|---:|---:|
| 门控＋升维、降维（含 MTP 草稿 FFN） | 485.547 ms | 46.29% |
| 其他矩阵乘 | 216.872 ms | 20.67% |
| 主模型＋草稿的词表投影 | 64.884 ms | 6.19% |
| 其他设备计算 | 149.367 ms | 14.24% |
| 无设备计算任务的区间并集 | 132.753 ms | 12.66% |

窗口从第一个硬件 MODEL_EXECUTE 到最后计算任务完成，长 1048.987 ms；排除输入处理，保留最终草稿工作。内核累加存在少量重叠，因此表中累计时间不要求严格加和等于窗口。

门控升维的 MTE2 活动占比约 98.76%、乘加活动约 11.55%；降维分别约 88.44%、15.47%。结合固定大权重、M=1→2 单次耗时接近，以及之前的权重读取证据，判断当前仍以读取/搬运权重为主。活动占比不是带宽峰值利用率，本轮没有新 HBM 字节或峰值饱和证明。

## 次要开销：MTP 图外流程

按完整的硬件图执行轮次划分，排除最后一个截断轮次后的中位数：

| 每轮阶段 | 普通基线 | MTP |
|---|---:|---:|
| 整轮 | 49.854 ms | 62.180 ms |
| 主模型图窗口 | 47.662 ms | 48.943 ms |
| 图结束到下一轮 | 2.193 ms | 13.237 ms |
| 上述图后区间的设备计算 | 2.008 ms | 5.270 ms |
| 上述图后区间的无计算任务时间 | 0.185 ms | 7.965 ms |

图窗口由 MODEL_EXECUTE 起点到该轮带有效 Model ID 的最后内核终点界定，不是 CPU 前向耗时。MTP 的候选草稿设置 enforce_eager=true；图外阶段包含词表投影、草稿、采样/校验和调度。

整段连续解码的无计算任务比例由基线 1.17% 增至 MTP 12.66%。三段最大的空档约 1 ms，重叠 CPU 操作包括 to/_to_copy、sub、diff、eq、fill、copy，支持进一步检查图外碎操作及下发。不能把全部空档都标为可消除 CPU 时间：短请求 profiler 对 Eager 路径也有开销，仍有同步和依赖。

这解释了为什么候选平均每轮产出约 1.86 token，而最终速度提高约 1.54 倍：每轮主模型时间接近原来，但额外草稿和图外流程增加了成本。两份数据的统计范围不同，该解释是时间线证据，不把两组平均值相除当精确成本模型。

下一处软件层面的检查范围是官方 MTP 草稿/采样的图模式和下发路径；本次没有切换开关、扩展候选数或重写内核，也没有承诺能消除所有空档。
