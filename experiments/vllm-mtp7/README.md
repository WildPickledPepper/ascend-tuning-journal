# 单卡 vLLM：MTP1 旧配置与 MTP7 草稿图

同一张 910B2、同一 vLLM/Ascend 源码、同四道 GSM8K、同一个评测器：旧配置 **30.443 token/s**，新配置 **59.389 token/s**，为原来的 **1.951 倍**。两组各输出 844 token、四题全对。新配置也比此前同四题 SGLang 单卡 **42.167 token/s** 快 40.84%；该框架比较的自然输出长度不同，不是普遍排名。

时间为 Asia/Shanghai，2026-10-20。新配置正式测试 15:13:38—15:13:52；旧配置补测 15:28:05—15:28:33。两次正常测速均未启用 profiler。

## 公平比较的范围

共同条件：Qwen3.8-27B，物理6单卡 TP1，权重 BF16，上下文4096，并发1，调度token上限512，无前缀缓存；相同请求 payload、GSM8K zero-shot chat、greedy T0/top_p1/top_k1、最大2048输出、自然结束；一次64-token预热。评测器固定 commit 和 SHA256 见证据。

|---|---|---|

| 每轮候选 | 1 | 7 |
| 草稿 | enforce_eager=true | 实际捕获并回放 merged draft FULL 图 |
| 主模型 | FULL_DECODE_ONLY，capture=2 | FULL_DECODE_ONLY，capture=8 |

## Insight 解释时间省在哪

先完成正常测速，随后用第1、3题的相同请求各截128 token，旧、新各采两份 CPU+NPU Level1/PipeUtilization、record_shapes 数据；不用截图，四份均导入编译版 Insight 后端并查询 operator/statistic。

| 采样指标 | 第1题旧→新 | 第3题旧→新 |
|---|---|---|
| 输出长度 | 128→128 | 128→128 |
| 主模型验证轮数 | 70→26 | 66→31 |
| 每轮主模型窗口中位数 | 49.056→52.152 ms | 49.042→52.155 ms |
| 完整验证周期中位数 | 65.218→75.086 ms | 65.150→75.109 ms |
| 两组主模型 FFN 累计内核时间 | 1966.277→752.792 ms | 1853.027→898.043 ms |
| 两组 FFN 累计时间 / 输出 token | 15.362→5.881 ms | 14.477→7.016 ms |
| 每周期无计算内核区间中位数 | 11.188→0.663 ms | 11.129→0.669 ms |

直接证据是 **主模型运行次数减少，一轮多处理候选，权重读取成本分摊给更多输出**。升维矩阵从 M=2 变成 M=8，单次并没有变快：第1题升维均值 **287.028→298.321 μs**，降维 **151.873→154.078 μs**；但64层矩阵乘调用数各从4480降到1664。两组权重形状不变，没有量化或修改 CANN 内核。

主模型图后窗口 **16.161→22.925 ms**，新周期反而长约10 ms，说明七步草稿有成本；它靠更少轮数赢得整段耗时。旧草稿设备计算累计约 **2.965 ms/轮**；新 merged draft 图约 **19.674 ms/轮**，不含图外准备。这些是累计内核时间，不能与可能重叠的CPU/窗口简单相加。

草稿图在新采样中有独立 Model ID，每主模型轮对应7次草稿FFN。分析按主模型64层FFN识别验证轮，不能把主模型和草稿的全部 MODEL_EXECUTE 都算成主模型轮数。四份图结构分别为70、66、52、62个回放命令，实际主模型轮数70、66、26、31。

新方案的无计算内核区间明显缩小，说明交替下发/等待的浪费更少；但该区间含DMA、控制与等待，不能全部叫CPU空转，也没有消融到“草稿图单独贡献多少”。旧CPU draft scope约7.94 ms/轮，新约18.74 ms/轮，包含设备等待；不能据此说新主机计算更慢。

剩余负担仍以矩阵乘为主。第1题新主模型 MatMul 累计1081.298 ms、草稿 MatMul475.822 ms；七步草稿也要读权重并计算词表输出。此次没有实现进一步优化。

## 后端、SQL和数据核对

- Insight 四份形状分组 **167+167+193+193=720**，调用次数和总时间逐组全部匹配 CSV，时间误差0 μs。
- SQL 使用 ascend-profiler-db-explorer 的 compute CTE 原文，四份各 TOP20 与CSV类型聚合匹配。当前没有SQL MCP，用只读SQLite连接执行；完整SQL和返回20行保留在过滤证据。
- 同配置的正常128-token请求与采样请求完整输出 token ID 相同。新配置第一个正常前缀3.731秒、采样2.298秒，有未隔离启动效应，不把这个差值解释成采样减少开销。
- 正式59.389/30.443来自无profiler四题结果，不能由128-token采样反推普遍极限。形状采样有开销，CPU包含时间和设备时间不相加。

## 运行、启动成本与恢复

成功新配置15:08:57开始、15:13:15就绪，加载、预热和图捕获约4分18秒；四题测速仅14.2秒。首次失败来自观察模块路径覆盖CANN的PYTHONPATH，导致acl导入失败，模型加载前退出；修正为追加并保留继承路径。失败不计测速。

按用户要求补旧配置时，改为“旧测速与采样→直接切新采样→只恢复一次”，省掉中间恢复。复用兼容缓存；编译hash不同时框架仍会编译，不能保证全部命中。没有新写NPU内核。

15:38:46恢复检查：原卡6单候选MTP、原卡7无投机基线均健康；临时8040关闭，卡7原进程始终未重启。实验配置保留，未将MTP7设为默认。
