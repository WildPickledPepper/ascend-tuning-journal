# BF16 按 L1 块重排权重：完整模型端到端结果

在物理 7 卡、Qwen3.8-27B、BF16、单并发、MTP7 和主模型/草稿模型图模式下，布局版相对已有优化 BF16 基线，使固定 512 token 请求 E2E 减少 **3.16%**，四道正常问答 E2E 减少 **2.76%**。生成阶段 TPOT 改善约 **3.3%**；首 token 平均增加约 **8–9 ms**。三组共 30 条测量请求的对应输出 token 完全一致，MTP 计数也一致。

这是完整模型服务请求测试，包含 attention、FFN、激活、残差、MTP 草稿、调度与 HTTP 流式接收。此前 [14.29% 的 gate/up 算子收益](../../kernels/gateup-l1-layout/results.md)属于局部算子结果。

## 对照与计时范围

| 项目 | 设置 |
|---|---|
| 硬件 | 同一物理 7 卡，Ascend 910B2，64 GiB |
| 模型 | 本地 Qwen3.8-27B；配置架构 Qwen3_5ForConditionalGeneration；64 层 dense 文本模型 |
| 精度/并行 | BF16，TP1，并发 1；mamba/SSM cache 均为 BF16 |
| 推测解码 | MTP7，主模型及草稿均启用图，capture size 8 |
| 调度 | max-model-len 4096，max-num-batched-tokens 512；prefix caching 关闭 |
| 共同优化 | 两组都保留此前验证的 M8 down-prefetch 内核 |
| 本轮唯一目标差异 | 主模型 64 层 gate/up 权重改为 L1 tile 连续布局，M8 使用已有布局内核 |
| Prefill/其他 M | 候选临时还原一层权重后执行原生 BF16 linear；该转换在请求计时内 |
| 服务 | 独立 localhost:8047，仅本次实验使用 |
| 测量 | 无 profiler；客户端 perf_counter；基线 A → 布局版 → 基线 B |

权重没有量化。原始 checkpoint 和已安装 vLLM 源码未修改。候选只常驻一份 gate/up 权重，64 层合计 22.817 GB；没有再常驻另一份完整 ND 权重。布局与原先算子实验完全相同，内核源码未修改。

E2E 从客户端发出请求至完整接收流式响应。TTFT 取首个返回 token，可能是 reasoning token。TPOT 为 `(E2E - TTFT)/(输出 token 数 - 1)`；MTP 可在一个响应块中返回多个 token，因此该指标与逐个响应块的 ITL 不同。输出吞吐为 `输出 token 总数 / 各请求 E2E 之和`，包含 TTFT，不包含请求之间保存日志的间隔。

每组排除两次预热后，测量：

1. GSM8K test 前两题，分别重复三次，每次固定生成 512 token，共 6 条请求。使用 ignore_eos，因此答案结束后的续写也计入；该组用于固定工作量比较。
2. GSM8K test 前四题，正常停止，上限 2048 token，共 4 条请求。输入分别为 121、83、114、92 token，输出分别为 137、44、575、88 token，共 844 token。

两组都是 temperature=0、top-p=1、top-k=1、request seed=42。此处只覆盖四道题，是输出一致性与性能检查，不构成完整 GSM8K 精度评估。

## 端到端结果

下表基线取 A/B 两次运行的合并均值。四题 E2E 总和按每组四次请求归一化，基线为两次总和的平均值。

| 指标 | 已优化 BF16 基线 | 布局版 | 变化 |
|---|---:|---:|---:|
| 固定 512 token：平均请求 E2E | 11.4325 s | 11.0716 s | 耗时降低 **3.156%** |
| 固定 512 token：输出吞吐 | 44.7847 token/s | 46.2443 token/s | 吞吐提高 **3.259%** |
| 固定 512 token：平均 TTFT | 355.257 ms | 363.567 ms | 增加 8.310 ms |
| 固定 512 token：加权 TPOT | 21.6776 ms | 20.9551 ms | 降低 **3.333%** |
| 正常问答：四题 E2E 之和 | 14.0536 s | 13.6662 s | 耗时降低 **2.756%** |
| 正常问答：输出吞吐 | 60.0559 token/s | 61.7580 token/s | 吞吐提高 **2.834%** |
| 正常问答：平均 TTFT | 348.153 ms | 357.114 ms | 增加 8.961 ms |
| 正常问答：加权 TPOT | 15.0726 ms | 14.5688 ms | 降低 **3.342%** |

固定长度与自然停止的 token/s 不能横向解释成模型能力差异：固定长度组在答案结束后继续生成，内容和 MTP 接受行为不同。每种协议内的基线与候选生成内容完全一致，可以配对比较。

基线复测稳定性：

| 协议 | 基线 A | 基线 B |
|---|---:|---:|
| 固定 512 token，平均 E2E | 11.4427 s | 11.4223 s |
| 正常问答，四题 E2E 总和 | 14.0704 s | 14.0367 s |

前后基线变化分别约 0.18% 和 0.24%，小于本次约 3% 的候选收益。这仍是同一天、同卡、小样本实验，尚未覆盖长输入、其他并发、其他 MTP 设置或长期服务负载。

## 数值、路径和工作量核验

- 接入前 smoke 检查：packed 权重还原逐位一致；M8 自定义路径及 M19/M512 回退路径输出与原生 BF16 逐位一致。
- 启动时 64 层实际权重逐层执行 pack → unpack 比对，全部逐位一致。
- 三组全部对应请求的 token 序列一致，包括重复请求；合计检查 11,748 个输出 token。这里只证明测试范围内的 token 一致，不声称所有输入的隐藏状态都已逐位检查。
- 每组测量窗口均为 1068 轮推测、7476 个 draft token、2862 个 accepted draft token；七个位置的接受计数也逐项一致。
- 审计确认候选 packed_count=64、主模型及草稿图捕获成功。候选 gate 自定义分发 128 次，发生于预热/捕获；图重放不会增加该主机计数，不能把 128 误认为完整推理只调用了 128 次算子。
- 候选 M8 使用布局内核；测量中的其他 M 使用还原后原生 linear。记录包括 M83、92、114、121；启动/预热还包括 M65、512。
- 两个基线 packed_count=0，三组 down 自定义分发计数均为 142。

## 为什么整网只改善约 3%

本次只缩短主模型每层 gate/up 的一部分时间。Attention、down、归一化、激活、MTP 草稿、采样和调度仍需要执行，局部算子的 14.29% 改善不会按同样比例作用于整段请求。

可用此前回放做量级核对：每层 gate/up 节省约 `279.176 - 239.276 = 39.9 μs`，64 层约 2.55 ms。用本次相同的 1068 轮推测作粗略估算，对应约 2.73 秒；本次每组十条请求实际 E2E 总和从平均 82.6485 秒降至 80.0961 秒，节省约 2.55 秒，量级相近。这个估算不代替整网分段 profiling，也未逐个验证推测轮次与设备调用的一一对应。

Prefill 仍需临时还原 ND 权重，该开销已包含在 E2E/TTFT 中。候选 TTFT 增加约 8–9 ms；本轮没有把这部分差额独立拆分为转换、调度和测量波动。结果支持当前短输入场景下 decode 收益能覆盖该集成代价。

## 启动与显存代价

- 64 层启动重排及逐位检查共 **14.552 秒**，从 steady request 计时排除，每次服务重启都要重新执行。
- 三次启动到 API ready 分别约 260.13、335.15、195.08 秒，包含导入、加载、编译和预热。缓存状态不同，不能把启动时间差全部归因于布局。
- 基线 B 启动日志记录 AOT 缓存加载失效，自动重新编译后成功捕获图；正式请求均在初始化和预热完成后计时。
- 两组加载的模型权重大小相同；候选临时还原工作空间使自动配置的可用 KV cache 从约 5.64 GiB 降到 5.34 GiB。两者均能容纳本次单请求 4096 token 上下文，未触发容量边界。
- 本轮没有重新采集整网 HBM/L2 计数器；此前算子回放约 0.5% 的 L2 命中率不能直接作为本轮整网命中率。
