## 词表构建

- 使用此前独立GSM8K train的64份主模型生成记录统计Top1024 token，并加入模型special token，共1032项。原test及其答案不用于拟合；当前请求的输入属于合法运行时上下文。
- 每个新请求清空动态历史，加入prompt token；之后每次主模型验证，从已算出的各位置logits取Top8，并刷新已有草稿候选的最近出现时间。
- 常用seed永久保留，其他token按最近出现顺序竞争剩余容量；4096行固定缓冲，无效候选槽的logit置为负无穷。所有位置的target预测仅作为候选提示，拒绝点后的预测不视为正确上下文。此前正文误写“未使用位置屏蔽”，后续核对本轮已归档源码SHA256确认实际有valid mask，修正文档，不代表追加了该实现。
- 设备上维护最近出现分数、TopK集合和ID映射；每主模型轮次将选中BF16权重行整理至连续缓冲，七次草稿投影复用。单流顺序执行，未实现异步gather重叠；全部开销计入E2E。
- 将选中ID排序，以沿用argmax的较小全局ID优先规则。图内始终使用固定buffer地址，候选更新不重新捕获图。

这是NanoSpec启发的混合方案，不是论文完整复现：没有计算prompt每位置的完整logits；用独立train seed辅助冷启动。固定4096是实际投影形状，并不表示每轮都有4096个有效词。仅支持本轮greedy/TP1/并发1，不能外推随机采样。

## 验证和计时

候选加载后用随机BF16隐藏向量，比较小head输出与完整head对应行。计时前两次预热，正式测试关闭profiler：前两道既有GSM8K题各两次固定512输出；原四题自然结束、输出上限2048；原1513-token长输入、固定128输出各一组。

`bench.py`调用既有流式请求工具。E2E包含HTTP、选词、权重整理、草稿和验证；输出吞吐定义为总输出token/各请求E2E总和，非并发服务容量。接受统计使用各组前后Prometheus计数差：accepted/drafts表示每轮接受的草稿数，另外报告1+accepted/drafts；末轮被长度上限丢弃的草稿工作仍可能计数。`analyze.py`离线重算各组指标、比较对应token序列。

原始日志、请求/输出token数组、seed及服务器部署路径保留在私有数据区；仅归档过滤摘要与必要脚本。实验结束关闭自己的服务进程组并核对7卡释放。
