# 当前ND/M8搬运瓶颈实采

**结论修正：旧NZ/M2存在的跨层TLB退化，没有在当前最快ND/M8配置复现。当前应优先研究BF16权重读取本身，大页不再列作第一优先级。**

2026-10-20，单张910B2物理6号、原生CANN、BF16主模型与SSM、MTP7草稿FULL图、主模型capture8。真实请求为GSM8K第1/3题各128输出token，开启profiler，不报告新的正常token/s。原始数据保留在私有采集环境；[过滤证据](../../evidence/2026-10-20/nd-m8-memory-diagnosis.json)。

## 真实模型：时间主要在GM→L1

| 单次主模型FFN算子，第1题 | kernel耗时 | MTE2活动 | MTE1活动 | MAC活动 | TLB miss/调用 |
|---|---:|---:|---:|---:|---:|
| 升维，8×5120乘34816×5120权重 | 296.938μs | 282.469μs | 78.726μs | 31.799μs | 192.552 |
| 降维，8×17408乘5120×17408权重 | 153.310μs | 129.050μs | 45.494μs | 22.395μs | 107.736 |

MTE2对应GM经缓存到片内L1的搬运路径，MTE1对应L1到L0，MAC对应乘加。这些流水并行，活动时间不能相加，也不等同于纯HBM或纯TLB串行等待时长。升维TLB miss比例约0.02746%，降维约0.02879%；第3题数值近似，目标FFN分组所有原始事件都满足hit+miss=request。

第1/3题主模型分别26/31轮，每轮每组64次。两组主FFN合计约**28.816/28.817ms/轮**；草稿词表投影`1,5120;248320,5120`每轮7次、每次约1.905/1.906ms，合计**13.337/13.342ms/轮**。筛选后的所有decode矩阵乘合计约61.609/61.623ms/轮。草稿词表投影MTE2活动约1.851ms/次，MAC约0.217ms/次，同样是主要的权重读取工作。

## 受控对照：TLB miss增多，没有让当前ND显著变慢

使用模型真实128份FFN权重，固定相同权重地址与同组输入/输出缓冲区；只改变读取顺序。small反复两层、full跨64层，均128个矩阵乘、相同逻辑权重读取量。每个PMU组6次图回放，稳定统计去掉前2次。

| 指标 | 反复两层 | 跨64层 |
|---|---:|---:|
| 升维TLB miss/调用 | 1.172 | 127.113 |
| 降维TLB miss/调用 | 0.227 | 71.215 |
| 升维kernel均值 | 279.840μs | 277.680μs |
| 降维kernel均值 | 151.536μs | 153.781μs |
| 无profiler，整图折合每个矩阵乘中位数 | 215.497μs | 215.474μs |
| 实采HBM读带宽，两轮 | 1.242535/1.242521TB/s | 1.242973/1.242886TB/s |

TLB未命中增加，但两组总耗时和带宽不变；当前ND数据不支持“跨层TLB退化是优先瓶颈”。这个判断来自受控耗时与硬件计数，不是单看miss百分比。HBM四单元均衡、时钟1600MHz；1.243TB/s是本轮隔离FFN图实测，不是完整模型带宽或硬件绝对上限。

升维L2读命中约0.506%、降维约6.565%，small/full相同。立即重读同一下降维权重时，L2命中接近100%，耗时**154.103→98.007μs**；升维立即重读仍不命中L2且未加速。降维权重170MiB可落在192MiB的L2内，但真实64层依赖不能靠把某层重复执行来直接兑现该收益。

## 搬了什么、多少

MemoryAccess的GM→L1计数：升维350000KiB，降维186592KiB；对应权重逻辑大小348160/174080KiB。small/full计数一致，当前请求字节的额外部分分别约0.53%/7.19%，含输入搬运和格式对齐等；尚未抓取本轮Tiling/DMA参数，不把差额精确分配给某条指令。**GM请求/片内写入计数不能当成物理HBM事务字节**，实际HBM带宽使用独立系统采集。

本轮另采Memory、MemoryL0和ResourceConflictRatio。ResourceConflictRatio输出仅提供向量冲突字段，目标为AI Core矩阵乘，不能据此声称已量出TLB stall、内存控制器队列或bank冲突。Memory/MemoryL0中的工具带宽保留原值，不将其直接当作整卡HBM带宽相加。

## 验证、边界与恢复

- 15份PyTorch采样均有Stop元数据、设备end_info、Text/DB、非空soc_pmu.csv；128145条非零请求SMMU事件的miss比例与官方CSV逐条核对。捕获阶段个别全局事件的hit+miss恒等式有偏差，其中1条在请求前处理的非目标词表投影；真实目标FFN分组没有此偏差。没有用该偏差外推目标FFN耗时。
- 编译版Insight后端导入真实模型及4份关键对照，35个矩阵分组调用数和均值与CSV一致。Insight统一DB仍未直接暴露TLB字段；SMMU来自msprof原始记录与官方CSV。
- 隔离图使用`torch.mm(out=)`/aclnnMm，模型使用原生F.linear/aclnnMatmul。两者绝对时间差，尤其升维约19μs，不能直接归因TLB、tiling或某个地址；本轮没有记录实际Tiling包或逐条DMA，也没有证明该差额全部来自某一机制。
- 16:49:44首轮启动，复用编译缓存出现解包错误；16:54:33自动恢复。16:54:40第二次启动改独立缓存，17:00:00服务就绪。完整请求与硬件采集在17:00–17:04附近完成；17:08:04（Asia/Shanghai）确认恢复原6号MTP服务，两服务HTTP200，7号原进程未重启，实验8040关闭。时间来源为采集回执和控制器。
- 没有修改内核、BF16精度、大页、驱动或其他用户的设备。没有将当前实验设为默认，也没有新增整模型正常性能成绩。

下一步优先核对**同一aclnnMatmul路径下**的实际分块、输入复用与搬运参数，围绕已经确认的GM→L1权重读取成本展开。当前证据不支持优先推动全局大页，也不能承诺仅调分配器即可提速。

## 复算入口

`capture_bootstrap.py`在图捕获之前启动SMMU/Pipe采集；`graph_audit.py`提供请求标记、停止采集及隔离探针RPC；`observe_weights.py`原样调用F.linear并记录地址，保留两层M8缓冲区。沿用旧RPC/环境变量中的nz命名只是接口兼容，本轮权重明确为ND。

`analyze_model.py`按CPU标记筛选真实请求，再将原始SMMU记录逐stream/task对齐；`analyze_hardware.py`检查读取顺序、地址、计数、L2和HBM覆盖；`backend-query.cjs`调用已编译Insight后端；`export_evidence.py`校验15份采样及后端结果。原始目录与登录信息不入库。
