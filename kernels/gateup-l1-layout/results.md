# 按 L1 块重排 BF16 权重：910B2 上板结果

结论：在本次 64 层真实 FFN 权重工作集上，按 L1 块连续存放权重，使 M=8 gate/up 耗时相对原生 BF16 降低 **14.29%**，相对相同计算模板的跨步 NZ 对照降低 **19.13%**。L2 命中率和每层实际 HBM 读取量几乎不变，支持有效搬运效率提高这一解释。本页记录算子回放；随后补测的 [完整模型端到端结果](../../experiments/gateup-l1-layout-e2e/results.md)显示，当前单并发 MTP7 场景 E2E 降低约 2.76%–3.16%。

## 2. 关键数据 TOP5

1. **无 profiler 的完整工作集耗时**：

| 实现 | gate/up，每层 μs | gate/up＋down 线性算子回放，每层 μs |
|---|---:|---:|
| 原生 BF16 | 279.176 | 429.775 |
| 相同模板、跨步 NZ | 295.871 | 447.693 |
| 相同模板、按块连续 NZ | 239.276 | 390.725 |

按块版本相对原生 gate/up 时间减少 14.29%，对应加速比 1.1668×；对配对的跨步 NZ 时间减少 19.13%，对应 1.2365×。gate/up＋down 线性回放时间减少 9.09%。上述“每层”是完整图耗时除以 64，不是挑选最快的单层 kernel。

两个独立运行的 gate/up 中位数分别为：原生 279.289/279.074 μs；跨步 NZ 295.815/295.903 μs；按块 NZ 239.306/239.254 μs。反向重复未改变结论。

2. **L2 读取命中率仍然很低**，按每次实际 hit/miss 求和加权：

| 实现 | gate/up L2 命中率 | gate/up 采样调用数 |
|---|---:|---:|
| 原生 BF16 | 0.5060% | 128 |
| 跨步 NZ | 0.5040% | 128 |
| 按块 NZ | 0.5039% | 128 |

3. **每层实际 HBM 读取量接近，持续带宽提高**。此项为 gate/up＋down 交替回放时的物理 7 卡总读流量：

| 实现 | HBM 读取 MB/层 | HBM 持续读取 TB/s |
|---|---:|---:|
| 原生 BF16 | 535.8645 | 1.2454 |
| 跨步 NZ | 535.9488 | 1.1986 |
| 按块 NZ | 535.8062 | 1.3715 |

三者每层读取量的最大相对差异约 0.027%。每种布局获得约 500 个稳态采样点，均含四个 HBM 控制器；前后半窗口的字节/层估计一致。采样使用整卡计数器，未对某个权重地址单独归因。

4. **数值检查通过**：最终八组输入覆盖不同幅度及零输入，三种自定义布局均与原生输出逐位一致；每布局 120 次图重放，在 12 次输入更新后继续与原生对比。完整工作集加载阶段逐层检查，64 层输出均逐位一致；NZ 和 packed 权重还原为原始 BF16 后逐位一致。这是已测试范围的结论。

5. **带宽口径区分**：用 gate/up 的有效权重字节数除以整个算子时间，得到原生 1.2770 TB/s、跨步 NZ 1.2050 TB/s、按块 NZ 1.4900 TB/s。它是有效权重供给速率，不能当作独立测得的 HBM 接口峰值，也不能与上表不同运行范围的系统带宽混用。

## 3. 核心瓶颈 TOP5

本轮有依据的结论只有三项，不补足五项。

1. **跨步取块是当前实现中的可改善因素。**同一模板的计算、分块和预取安排保持一致，连续布局比跨步 NZ 更快，且 L2 hit/miss 和实际 HBM 字节数接近。证据支持存储布局/读请求组织的改善。
2. **低 L2 命中率不意味着已经达到有效带宽上限。**候选在同样约 0.5% gate/up 命中率下仍提速，不能仅由 miss 比例判断搬运不可优化。
3. **HBM→L2 与 L2→L1 的独立耗时尚未拆开。**这些数据证明整个供数路径的有效吞吐提高，不能单独断言收益来自 HBM bank、L2 bank、地址转换或某段互连。连续布局也改变地址分布，相关机制仍需更细的硬件指标或受控变体研究。

## 4. 优化建议 TOP5

1. 保留该按块布局作为 M=8 gate/up 候选。已有独立回放收益，但接入前需要满足不同输入 M/prefill 对同份权重的读取需求。
2. down 若另做按块方案，需要独立设计尾块和保持原生 K 顺序，不能把本轮 gate/up 的 14.29%直接套用到 down。
3. 整网验证应同时测无 profiler 的 TPOT/吞吐、prefill 和加载成本，并确认权重不需要常驻双份。本轮不据此报告整网提升。

## 数据完整性、限制与资源状态

- 框架 profiler 报告了默认 schedule 和 ACL→NPU flow 关联警告。每个 L2 结果已核对 256 个设备算子、其中 128 个 gate/up，指标列完整；本轮只使用设备时间和计数器，不使用失败的 host 关联。正式性能取自独立无 profiler 计时。
- `--sys-devices` 在 application 模式下被工具提示忽略；进程环境限定物理 7 卡，并通过导出 HBM 表仅包含 deviceId=7 验证实际采样范围。
- 7 卡在实验开始前已有端口 link down 告警 `81078603`；实验未修改端口或设备配置。各版本同卡对照且反向重复稳定。告警保留在环境记录中。
- 本轮为 64 层 gate/up 和 down 线性算子回放，采用固定随机输入；未串接激活函数、残差或真实前后层依赖，未执行完整模型生成。
- 未修改在线服务或模型文件；所有上板进程均有明确结束点。最终卡状态保存于证据包 `environment.json`。
- 源码位于 `kernels/gateup-l1-layout/`；原始 profiler 数据仍在服务器同名目录 `results/`，本地证据包有 manifest/SHA256。未自动提交 Git。
