## 最近一次记录的状态

- 当前目标：**保持 BF16，依据 ms 工具证据调优单卡推理**。
- 模型：Qwen3.8-27B，Dense，单卡 TP=1；模型文件保留，6 号卡服务已停。
- 已实施并验证：切换为 `FULL_DECODE_ONLY` 图模式，3 次无 profiler 基准的生成速度中位数 **5.55 → 20.28 token/s，约 3.66 倍**。
- 已定位：门控＋升维、降维两组前馈矩阵乘合计占连续解码时间约 **55.9%**，主要负担是权重读取。
- 已澄清：降维算子“多 21.6%”的计数由 **14.375% L1 清零＋7.1875% 输入 ND→NZ 写请求**构成，不能当作显存重复读量或提速比例。
- 已实现独立 BF16 降维内核：输入搬运 **68→34 次/核**，清零 **68→2 次/核**，并增加双缓冲。Insight 后端与上板计数完成交叉核验。
- 单算子同卡交替图回放：CANN **154.51 μs → 自写版本 142.41 μs，耗时下降约 7.83%**；不能当作整模型 token/s 提升。
- 尚未接入模型：自写版本优化前后逐位一致，但与 CANN 有少量 BF16 输出差异，原因未完全确认；还需要正式 Torch NPU 算子封装和模型验证。[实验代码与限制](kernels/down-reuse/README.md)。
- 最后设备检查（14:53:11）：6、7 号卡均无进程；未修改共享 CANN、驱动或其他账号环境。

这里的状态是历史记录，不是实时监控。详细配置、测量条件和限制见当天日志。
